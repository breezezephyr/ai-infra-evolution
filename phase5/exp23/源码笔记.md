## A：真实DSpark沿哪几次交接前进

| 环节 | 固定源码 | 能证明的范围 |
|---|---|---|
| 草稿生成 | `models/mtp/dflash.py:279` `DFlash.sample_drafts` | 生成最大长度D的草稿；本轮验证长度由后续调度选择 |
| 全批验证预算 | `csrc/engine/mtp_varlen.hpp:150` `MTPVarlen::schedule` | 在B=n+k的候选间比较预期提交量与graph/采样耗时估计；同收益倾向较小预算 |
| 请求间分配 | `tilelang_ops/schedule_mtp_varlen.py:35` reference | 累积置信度排序，按全局额外预算分配；同分按展平顺序 |
| 接受与拒绝重采样 | `tilelang_ops/fused_sample.py:227` reference | 目标/草稿分布比值与随机数决定接受；残差分布用于拒绝后采样；confidence head不是最终验收结果 |
| 连续前缀 | `tilelang_ops/sampler.py:227` `get_accept_result_ref` | 首个拒绝后的草稿不再成为本轮有效接受；额外输出行与golden override另有语义 |
| 提交与KV计数 | `csrc/engine/scheduler.hpp:955`、`sequence.hpp:216` | 逐token检查停止条件；用真实提交量c回填乐观推进的processed token计数 |
| grammar临时回滚 | `layers/sampler.py:352` | 构造本轮mask时临时消费草稿后撤销，与KV计数修正分开 |

上述路径来自源代码阅读，没有运行后端kernel来验证随机流和数值行为。默认`DEEPINFER_USE_NEXTN_DECODE=5`表示最大草稿长度，`DEEPINFER_ENABLE_MTP_VARLEN`控制可变验证调度。

调度使用不同轮次的信息：总预算使用N−2轮估计，N−1轮信息用于请求间分配；ZOS存在在途元数据，设备端还会修正。`MTPVarlen::schedule`在没有性能曲线时有验证全部现有草稿的回退。不能把实现简化为每请求一个固定confidence阈值。

常见计数差一：每请求`seqlen_q`为验证草稿数+1；接受a个草稿，通常提交a+1个结果，但EOS/停止可截短。`last_valid_offset=a`不包含额外token；KV修正使用实际提交c，与最大D分开。

## A教学重放额外假设

`replay.py`与`run.py`不导入以上源码函数。它们使用给定目标序列、预设草稿对错与合成置信度，按确定性oracle验收，不实现p/q分布拒绝采样。候选规则为累计置信度乘积≥0.8的最长前缀，允许0，**不是DSpark的预算策略**。

教学模型还允许策略改变实际起草数量，草稿工作按选定长度计费。真实DFlash会生成最大D，再决定验证其中多少；真实模型起草成本、验证kernel曲线、缓存和ZOS不能用这张成本表替代。工作点是声明的算账假设，不是实测时间；目标token相等是这个oracle状态机的不变量，不是模型输出质量结论。

## B：实际SWA边界，不把推荐值写成下限

- `environ.py:129–132`：B=`max(raw_B,nextn+1)`；未设置raw_B按0。默认nextn5，B至少6；nextn0时B仍至少1。
- `worker/model_runner.py:106–114`：开启mask/compact时，Python原始断言要求W>0、K≥W+B。断言块受Python优化模式影响。
- `prepare_tensor_input_v4.cpp:349`：正常prompt metadata路径还有K>0、K≥W+B的C++检查；本轮没有执行这些C++检查。
- `model_metadata_utils.py:87`：模型还需consumer层、n_prefill_layer>0等前提。局部下限通过不是模型加载或服务运行通过。

因此W128、nextn5、raw_B≤6时，K133触发局部下限拒绝，134刚通过；README推荐140不是数学最小值。B是配置容量预算，不应直接叫nextn或某个未证实的seq_rollback接口。

## B：mask与compact具体保留什么

固定C++代码以N=`seq_data->get_len()`为锚。逻辑后缀与当前prefill chunk相交；抢占重算时N可以包含已生成token，不能始终当作原始prompt长度。

对绝对query位置p，可见域左端为`clamp(max(p−W+1,N−K,swa_valid_start),0,p+1)`，右端p+1。有效状态起点`swa_valid_start`不能忽略；官方Python `_reference_visible`没有这个参数，只覆盖正常valid_start=0的参考路径。

mask保留全部query行，改变SWA索引可见域；compact在consumer边界移除可裁行，但保留原绝对位置。`clip=clamp(N−K−q_start,0,q_len−1)`意味着完全处于保留后缀之前的chunk仍有1行占位，其store slot=-1，不代表要缓存这行的SWA状态。采样需要合法输出行，不能改成空batch。consumer前的层仍沿full布局，decode不走这套prefill截行。

部署说明`doc/inference_deployment_qa.md:183`明确描述近似SWA状态。mask/compact可见域或metadata相同，不足以证明与完整历史的模型结果相同。

## 实际执行的官方源函数隔离探针

`source_probes.py`在Python3.12执行下列内容：

1. 完整`environ.py`放入新内存模块，再把模块的os引用换成只读受控配置字典的getenv。每例新模块，未读取真实主机配置或凭证。
2. AST原样提取`ModelRunner.load_model`里的mode断言块，注入self.window_size和真实源解析器的envs；不调用load_model或get_model。显式正常assert编译模式。
3. AST提取官方`SeqSpec/MaskCase/build_mask_cases/_reference_visible/_expand_pivots`，不导入示例脚本中加载DeepInfer扩展的部分。

16配置：7局部guard通过、5guard拒绝、4解析拒绝，16/16符合预定判定。10个官方形状产生5216次参考函数调用，与有限集合交集核对一致；3个手工pivot展开案例及1个描述符缓存/rearm控制通过。5216是重复参考行检查，不是模型请求，也不是C++metadata比较。

完整`prepare_prompt_v4`及官方L1仍依赖扩展/pinned内存等条件，官方L1要求可见GPU；本轮未执行，因此不宣称真实mask/compact metadata等价或模型等价。

## B教学反例的独立范围

99个案例是多层窗口整数求和，既无attention权重，也无RoPE、模型缓存或confidence。mask/compact只是同一个有限可见域的两种教学表示，不是上述C++两种布局的复刻。它们99次相等，但只54次等于完整历史；18次覆盖一层窗口及回看范围，仍因跨层依赖而不同。

另列16整数例：W4、回看2步、保留6、2层，裁剪两种表示均120，完整历史176。本玩具跨层依赖的充分保留公式是`L(W−1)+1+B`，不能拿它替换DeepInfer的真实配置约束，也不能把数值差换算成模型质量损失。
