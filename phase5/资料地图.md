已核对的关键边界：

- `render_conversation`生成DeepSeek格式prompt；encode还要求匹配的tokenizer。把模型名注册为别名只解决版本映射，不把另一种模型变成DeepSeek。
- 用户正文里的特殊token拼写与模板显式special token不是一回事；自行tokenize整条prompt时忽略`special_ranges`会改变语义。
- token流可缓冲尚未完整的多token字符；Text chunk没有token边界，其标记按拼写匹配。HTTP任意字节切分、文本chunk、token ID chunk需要分层测试。
- reasoning计量依赖附加tokenizer。未计量时协议可能省略或给默认0，账本需要另记来源/可测状态。
- `server-py`默认是mock inference，当前processor不附加tokenizer，接受Text而非Tokens chunk；不能把独立token-stream示例的能力直接安到该server上。
- 示例默认对Responses的web_search声明丢弃、对Messages的声明拒绝；配置可以改变。这里的“兼容三协议”需要逐能力描述。
- schema转换、写入prompt和后端执行约束是不同层；logprobs由后端提供，库不会替模型算概率。
- 核心路线先做文本；图像预处理/URL访问和真实视觉推理不是一次文本安装成功就附带完成的能力。

## 3. DeepInfer：按实际调用链读

固定版本的离线链路（不是HTTP在线服务）：

```text
examples/offline_inference.py
→ LLM.generate / _add_request
→ LLMEngine.add_request → Sequence → scheduler.add_sequence
→ LLMEngine.step → C++ Scheduler.schedule
→ Worker.execute_model_step
→ ModelRunner.execute_main_model / execute_sample
→ post_process → scheduler.process_outputs
→ build_request_outputs → RequestOutput → token/文本
```

已核对的边界：

- 支持的模型和设备按README声明记录；本轮不把8GB小模型结果当作DeepInfer实测。
- DP共同选择步型不等于外部请求跨副本负载均衡。内部KV系统也不等于已经交付完整跨实例KV服务。
- ZOS底层EnvVar缺省为False，但标准离线NORMAL路径经过EngineArgs构造后以setdefault默认启用并重置解析缓存；COMPLETION同样默认启用，PROMPT默认关闭，已设置的环境值优先。因此不能只读environ.py就断言标准离线入口默认不启用异步调度。本项是源码链路核对，本次未运行原实现。
- 确定性采样的官方条件包括NVIDIA、batch-invariant、固定`seq_seed`及禁用动态MTP验证。实际有效配置、版本和完整前提要一并保存。
- DSpark依赖草稿/置信度及硬件成本信息；普通小模型投机解码不能直接换名为DSpark。
- SWA bounded replay有近似与特定模型结构前提；`keep_tokens >= window + max_backtracking`是必要配置边界之一，不能据此推导所有任务质量不变。YoCo L1虽不加载权重，仍依赖已编译扩展和可见GPU，不能作为现成纯CPU验证入口。
- PPL回归是特定生成轨迹/平台/工作负载的检查，不能当成通用语料PPL；性能图中的满接受或假定接受率与实际接受输出吞吐要分开。profiler时间不直接转成正常稳态吞吐。

## 4. recipe与DeepInfer之间还需要的接缝

目前所查官方示例未提供现成的recipe→DeepInfer在线backend；DeepInfer eval读取checkpoint里的`encoding/encoding.py`。两者有潜在可接接口，不等于开箱即用。

未来真实接入至少要核对：

1. Conversation/prompt与模型、tokenizer、模板revision匹配，实际token IDs一致。
2. 生成参数/默认值/上下文上限、停止条件和finish reason映射。
3. 请求生命周期、流迭代、取消、输出与线程/设备收尾。
4. sampler约束：recipe中`tool_call*`类约束不能直接透传给只接受JSON/regex/EBNF种类的compiler，须有明确适配或拒绝。
5. usage、草稿/验证/接受/交付token与错误的来源；mock记录不能被当成后端测量。

这也是P5·1～3的价值：读懂可接缝与不兼容点，避免仅凭两个仓库都叫DeepSeek就假定直接相连。
