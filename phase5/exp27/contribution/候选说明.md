## 触发、预期与本次实测

最小条件：请求转换成功，未设置 `max_tokens`，随后调用 `resolve_max_tokens(P, C)`，其中 `P == C`。这里比较的是调用方传入的计数参数，不是探测真实模型容量。

固定 Rust 实现先检查 `P + requested > C`，省略额度时 `requested=0`；之后执行 `.min(C-P).max(1)`。因此零余量时省略额度仍返回 1；显式设置 1 则先触发超界错误。依据：[固定／当前源码](https://github.com/deepseek-ai/deepseek-recipe/blob/935817c66f5d6e64838f419692545f06787e485f/deepseek-recipe/src/request/mod.rs#L182-L235)、[Python stub](https://github.com/deepseek-ai/deepseek-recipe/blob/935817c66f5d6e64838f419692545f06787e485f/deepseek-recipe-python/python/deepseek_recipe/_native.pyi#L521-L533)、[英文指南](https://github.com/deepseek-ai/deepseek-recipe/blob/935817c66f5d6e64838f419692545f06787e485f/docs/tokenizer.md#L78-L87)、[中文指南](https://github.com/deepseek-ai/deepseek-recipe/blob/935817c66f5d6e64838f419692545f06787e485f/docs/tokenizer.zh.md#L50)。

本次 [repro.py](repro.py) 使用 exp19 的真实请求和本地 V4.1 tokenizer，经真实 recipe native 转换与编码得到 **P=41**，两种额度设置得到相同 token IDs。然后人为传入 C=40/41/42：

| C / 剩余 | 省略额度：源码预期 → 实测 | 显式 max_tokens=1：源码预期 → 实测 |
|---|---|---|
| 40 / -1 | ConversionError 400 → 相符 | ConversionError 400 → 相符 |
| 41 / 0 | 返回 1 → 相符 | ConversionError 400 → 相符 |
| 42 / 1 | 返回 1 → 相符 | 返回 1 → 相符 |

**6 次 helper 调用，不是 6 次模型生成。** 原始 token IDs、请求、合成 context 参数、返回值和完整错误正文保存在 [repro.stdout.json](evidence/repro.stdout.json)；历史三协议原始反例提取在 [historical-counterexample.json](evidence/historical-counterexample.json)，含源文件 SHA256。独立测试使用人为 P=100、C=99/100/101，明确不把 `hi` 的实际长度冒充 100。

预期的贡献结果是指南明确记载现有行为，并用绑定测试防止文档与所测行为失配；不预设“返回值为正必然满足 P+M≤C”，也不把这个例子外推为后端一定接受／拒绝。
