# Phase5结题：能力、故障与迁移

| 范围 | 已实现/如何验 | 迁移要求与限制 |
|---|---|---|
| 请求输入 | 原生Qwen模板、文本messages、固定参数/预算 | recipe CPU合约是独立路径；模型/tokenizer/template/revision须重验 |
| 直通/集成 | 同批同题固定seed，对照到客户端原始SSE | 集成整段规则门控，首内容定义不同；不是裸kernel性能比较 |
| 精确响应缓存 | 租户/模型身份/模板/策略/实际输入组成key，原origin可追 | 缓存非KV；应用冷暖非GPU冷启动，真实多实例需共享一致性 |
| 准入与突发 | 1活跃+1等待，6请求突发及拒绝保留 | 并发不等于到达率；没有生产容量结论 |
| 输出审核 | LAB_BLOCK整段实验规则，拒绝也留attempt用量 | 不代表通用安全/事实质量；完整缓冲增加交付等待 |
| 重试 | 未提交、无外部副作用、有key、可重试、最多2attempt | 同GPU逻辑目标非HA；工具/外部副作用未执行 |
| 已提交断流 | 明确失败终态，不拼第二份回答 | 部分已交付内容不可撤回；产品重试需新交互 |
| 取消/排空 | 当前generation交付封闭、worker join、native CPU clear分列 | HTTPclose不等于kernel stop，未做音频播放/会话分钟计量 |
| 原生usage | 全attempt、失败重试保留，unknown=null，来源对账 | 已知小计非完整费用；持久账本/真实费率/GPU归属待接 |
| 资源 | supervisor同钟区间并集、CPU wait4、PID/端口/modelhash回读 | 包含观测开销；权重驻留精确区间和kernel秒未知 |
| 源码线 | recipe原库CPU、DeepInfer源码与局部probe、Mooncake Store API | DeepInfer完整引擎/真实P-D/KV导入未运行，不能迁移成功率 |
| 贡献 | recipe满context额度文档与绑定测试最小候选 | 已有上游讨论，本地验证未提交；上游决定契约与接收 |

接入HiMarket/Higress前至少重新确认真实身份、可支持协议、模型模板、租户限额、路由故障域、流式提交点、持久结算幂等、审计存储、配置版本与回滚。本文仅列迁移检查项，本轮没有修改这些生产系统。

本轮每个故障case的完整输入、期望终态、实际attempt数和注入位置以[冻结计划](../results/exp27/formal-v2/plan.json)及[同批摘要](../results/exp27/formal-v2/summary.json)为准。exp26更完整的受控故障矩阵仍单独保留，不把其通过数加进本次42。
