# P5·3 系列图形验收

产物仅写入本目录。复用前篇 `21-Phase5·2-广播分几段/img/` 的 `cover.py`、`build.py`、`render.py`，在本目录副本中修改文案与检查逻辑。前篇全部 13 个文件的 SHA256 前后相同，证据见 `source-hashes.json` 和 `图卡检查.json`。

| 产物 | HTML | PNG | 实际像素 |
| --- | --- | --- | --- |
| 深色系列封面 | `00-封面.html` | `00-封面.png` | 2560 × 1090 |
| 米色解释图卡 | `01-一页纸.html` | `01-一页纸.png` | 2160 × 4160 |

封面保留七站路线，只有站 5 全亮，色值 `#F2D479`；其余站透明度 0.28。标题、副标题与眉题按本次要求设置。

图卡保留“老做法 / 哪里失效 / 新方案 / 怎么验”。五栏依次为声明、CPU 线真实 recipe 转换、两线显式语义映射核对或拒绝、GPU 线后端独立采样生成、独立 JSON / schema / 业务校验。移除串行箭头，在转换与后端之间采用虚线分隔，避免把核对框架误读为已接通的执行链。

范围更新为“CPU 真实 recipe 转换＋小 GPU 后端独立对照”。事实依据是用户本轮提供的实验更新：CPU 真实 recipe 转换与 parser 探针、DARYU 4060 / vLLM 0.8.5 / Qwen3-0.6B 原生模板下的实际 GPU 生成属于两条独立实验线。图中保留版本和模型标识，不填实验数量或结果比率。

图卡明确 recipe prompt / OutputConstraint 未直接接入 Qwen、两线未端到端集成、未运行 DeepInfer。任务、seed、原生 Qwen 模板、API 入口实际设置及响应均列为验证要求；拒绝、失败和未知保留分母。本版本数组 maxItems 被 HTTP 400 拒绝，不能静默削弱 schema。工具只作声明，不执行。

验证证据：

- `00-封面.layout.json`、`01-一页纸.layout.json`：DOM 尺寸、字体、文本边界、兄弟元素矩形交叠及脚本错误。对嵌套父节点也执行检查；同行网格使用二维矩形交叠判断。
- `图卡检查.json`：尺寸、内容、两线边界、七站高亮、前篇哈希核对和重复渲染哈希；逐图记录兄弟元素与文本矩形检查数量。所有溢出、重叠、脚本错误列表为空。
- `视觉复核.json`：通过 `view_image` 实际查看两张最终 PNG，并绑定所查看文件的 SHA256。观察主副标题、四块内容、五层流程、范围与页脚，无裁切或遮挡。
- `sha256-manifest.json`：本目录交付文件哈希。

确定性验证限定在相同机器、Chrome 与系统字体环境；两次渲染的 HTML、PNG、布局报告 SHA256 一致。全部绘图由 HTML/CSS/SVG/Canvas 与本地 Chrome 完成。图形脚本没有调用图片生成服务、模型推理或 DeepInfer；所描述实验事实来自用户本轮更新，图形制作不重复执行这些实验。

复现（从本目录执行）：

```sh
python3 -B -m http.server 4313 --bind 127.0.0.1 --directory .
```

另开终端执行：

```sh
SERIES_PREVIEW_URL=http://127.0.0.1:4313 python3 -B verify.py --rerender
```

首次构建可分别运行 `cover.py` 与 `build.py`；`verify.py --rerender` 在已有产物上重复渲染并比较哈希。临时 Chrome profile 位于本目录并自动清理。
