# exp14 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 实现单流 GPU 语音级联，完成三种端点/TTS策略的真实测量，提供可回查事件、音频与浏览器播放证据。

**Architecture:** Mac 生成固定语音输入，按实时采样节奏经 WebSocket 发送到 DARYU；CPU Silero 判端点，GPU Whisper/Qwen3/Kokoro 处理，客户端记录完整音频与播放位置。三个模式复用模型，取消后等待真实线程结束才进入下一回合。

**Tech Stack:** Python、aiohttp、PyTorch/CUDA、CTranslate2/faster-whisper、Kokoro/misaki、Silero VAD、Web Audio。

**Spec:** `phase4/exp14/设计.md`

## Global Constraints

- 单声道 PCM16 16 kHz；20 ms 传输帧。
- 单回合上下文先限制1024输入 token；音频最长15秒；输出96 token。
- 三模型共驻/运行以最多约6.5 GiB为试验保护预算，预留余量。
- ASR、LLM、TTS 的模型推理均必须证明在 GPU 上执行。
- 发送音频队列以最多2秒样本量为界，TTS待处理文本最多2段。
- 每条每模式3次，共108条；同一条内轮换模式顺序。热身另存不混入。
- 没有可靠映射或输出API时保留原始事件，相关派生字段为 null。
- 不修改既有 vLLM 环境和服务；当前目录不是 Git 仓库，使用文件哈希与运行回执追踪版本。

## Review Focus

- 奇数PCM字节、错误序号或旧generation：拒绝无效帧，旧轮次不能播放；Task 1测试。
- 句中停顿导致提前端点：保留完整输入证据并单列失败，不能算低延迟成功；Task 4/5测试。
- 模型调用被取消但线程未退出：等待实际返回；不让下一轮覆盖状态；Task 3/4测试。
- 音频静音开头、浏览器暂停或队列欠载：首PCM和首非静音渲染分开，无法播放时保留null；Task 5测试。
- 多个运行时的GPU显存分配与隐式CPU回退：组件记录设备/精度，进程级显存采样；Task 3实测。

**Interfaces:**

