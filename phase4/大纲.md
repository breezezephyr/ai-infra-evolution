# Phase 4 · 实时多模态：从一次请求到一段会话

> 设计稿，2026-10-22。承接 P3b·4，保留公交车比喻：前面安排一趟车，这一阶段安排乘客持续说话、听话、插话的一段旅程。本大纲保留阶段设计；exp14～17已完成，GPU/浏览器/合成队列边界见各自结论，exp18仍为计划。

## 一、目标与约束

为系列读者做一个能追踪完整回合的语音 demo：从输入音频的最后一个语音样本，到服务端音频生成、客户端接收、渲染及设备输出时间估计，逐段留下证据。再验证插话后哪里停止、哪些历史保留、会话排空怎么做，最后按会话分钟核算资源。

沿用既有约束：以 DARYU 的 RTX 4060 Laptop 8 GB 做小实验；先实测，再写正文和图卡。可重放的合成输入、浏览器真实播放、纸面推导分别标明。先覆盖语音，视频另设有界验证。

800 ms 为本系列的探索目标，不当作普遍的人类感知阈值或现成服务承诺。每项结果说明输入、模型、并发、测量边界和失败分母。

## 二、路线选择

| 路线 | 能验证什么 | 代价与限制 | 本轮选择 |
|---|---|---|---|
| 本地小模型级联 | VAD、ASR、LLM、TTS 的等待与交叠，同卡资源与取消 | 多段调度；识别/合成质量限制；需实测能否常驻 | 主线，先做 exp14 |
| 托管级联或 Realtime API | 接口可用性、网络、厂商会话协议 | 需账号/计费，内部阶段不一定可观测 | 保留后续对照，不先引入费用 |
| 本地 Omni | 音频输入输出一体化路径 | 内存、量化、流式服务实现另有约束；不能复用级联的阶段定义 | 本阶段先做架构对照，另有可运行配置后再压测 |

第一组候选：Silero VAD（CPU）、Systran/faster-whisper-small（GPU INT8/FP16）、已有 Qwen3-0.6B（GPU BF16，关闭思考）、Kokoro-82M-v1.1-zh（GPU，中文固定音色）。CPU 的采样、VAD、分词/音素转换和网络处理也单独计时。

这是依据官方接口与模型规模作出的选型，不是已经跑通的兼容性结论。DARYU 本轮显存占用 350/8188 MiB；设计时尚未安装 ASR/TTS/VAD 依赖；目前已在独立venv完成CUDA验证。创建独立语音实验环境，固定成功运行后的包版本、模型 revision、文件哈希与设备。不能用静默 CPU 回退完成“GPU 实测”。

### exp15～18 的范围约束

- WebSocket 先用于本地可控基线；WebRTC 的价值从媒体处理、网络路径和故障表现验证。SSH/TCP 隧道中的 WS 与直连 UDP 不能宣称是纯协议公平对照，不能只靠注入应用层 sleep 推断真实丢包行为。
- 一台 GPU 可服务多个会话；会话亲和绑定状态拥有者，推理实例如何复用另测。仅有一台 DARYU 时，两个逻辑 worker 的排空实验不代表多 GPU 故障迁移。
- 插话记录检测时刻和真实输入起音，不能用服务端收到控制消息的时刻替代所有端到端起点。TTS 若只能在分句边界停止，计算停止的粒度照实写。
- 视频队列的采样/丢帧验证不等于视觉模型推理；没有实际视觉理解时，不填视觉编码时延或画面理解质量。
- exp18 以重算日志为主，不必为了算账再跑 GPU；需要新增资源测量时才补跑。GPU 常驻时长、活跃执行代理指标和 token 数不能互相冒充；价格须标注自定费率或实付来源。

## 四、共同观测规范

每个事件带 `session_id / turn_id / generation_id / component / event / clock_domain / monotonic_ns`；音频包带采样率、声道、样本数、序号和累计 sample offset。

服务器、浏览器各用自己的单调时钟计算本地差值。客户端音频重放的输入结束和输出渲染尽量放在同一时钟域；需要跨域对齐时另记时钟校准、往返与误差范围，不直接相减。每轮保留关键路径，重叠阶段不把耗时简单相加，分位数也不相加。

三层结束状态：

1. 回合：自然结束、长度限制、识别/合成失败、取消、客户端断开、播放欠载等。
2. 计算：停止信号、模型调用返回、生成线程/进程退出、队列是否清空。
3. 播放：收到帧、渲染样本位置、设备输出估计、迟到旧轮次帧丢弃；可闻首声仅在有声学回环证据时填写。

音频首包包括静音时另计首个达到预先固定阈值的非静音样本。浏览器调用 `play()` 或收到首包都不当作已经听见。LiveKit 的某些播放延迟字段默认近零，不能直接拿来证明扬声器端延迟。
