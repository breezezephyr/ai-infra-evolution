# AI Infra 进化之路

从一次模型请求出发，理解推理服务怎样排队、生成、缓存、流式交付，并在失败后留下可以核对的证据。系列共 **28 篇文章**，配套代码按 `phase0`、`phase1`、`phase2`、`phase3`、`phase3b`、`phase4`、`phase5` 组织，实验编号为 **exp1–exp29，另含 exp8b 变体**。

文章用“公交车”串起资源约束与服务行为：先建立概念，再做单卡测量，最后连接网关、语音会话、协议与账本。每个实验都说明实际执行了什么；源码阅读、CPU 教学回放、真实原生库调用和 GPU 推理分别列证。

## 从哪里开始

第一次阅读可按 01–28 顺序推进。已有推理引擎经验，可从 05–06 的单卡测量开始；关注服务治理，可读 07–14；关注语音与会话，可读 15–19；关注协议、纵向网关和证据移交，可读 20–28。

想动手时，先查[实验表](docs/EXPERIMENTS.md)，进入对应阶段或实验 README，核对依赖、模型、硬件和输入，再选择离线分析或新一轮执行。脚本入口不等于跨环境一键复现；新运行使用独立输出目录，避免覆盖留存结果。

## 怎样理解实验结果

- **CPU 也有不同层次**：exp12 是历史日志离线账本；exp19/20 调用真实 recipe 原生 CPU 库；exp23 是教学回放和源码探针；exp24 调用真实非 CUDA Store API。这些实验不自动证明模型推理性能。
- **GPU 测量有具体环境**：前半段以单张 8 GB GPU 为主，模型和引擎配置随实验改变；不同组的绝对时延、吞吐和样本不能直接合并。CPU 侧取消记录也不等于 CUDA kernel 停止证明。
- **exp28 新生成数为 0**：图像接口健康检查失败后停止，没有提交本轮生成；会话或显存驻留迹象不能作为成功推理证据。
- **exp29 独立运行 4B 文本模型**：Kaggle 上 Qwen3-4B FP16、Transformers 4.51.3，模型仅用一张 GPU。5 个串行接口用例中 3 次生成，实际输出 41 token；没有重跑 exp25–27 网关，也没有将 exp28 改写为成功。
- **DeepInfer 等源码阅读与实际执行分开**：系列没有完成 recipe → DeepInfer 端到端模型推理；HTTP 200、流式收尾、答案质量、SLO 和计量正确性各有判据。
