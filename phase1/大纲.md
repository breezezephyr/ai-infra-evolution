## 二、每一圈，调度员按顺序做四个决定

这是 Phase 1 的主线，也是文章的骨架。每圈开车前：

**决定 1：车上现在有谁能继续坐**（running 队列）
- 上一圈拿到字的人，行李架各多一件。够不够放？不够 → 进入决定 3
- 有人拿到了结束符或到了 `max_tokens` → 下车，格子回收

**决定 2：站台上放谁上来**（waiting → running，准入）
- 条件：他的行李（prompt）加上预留的格子，车上放得下；本圈 token 预算（`max_num_batched_tokens`）还有余
- 先来先上（FCFS）还是有优先级。vLLM 默认 FCFS
- 行李里有几箱是寄存好的（prefix 命中），那几箱不用搬，只占格子

**决定 3：放不下了，请谁下车**（抢占）
- 请最晚上车的下（LIFO），把格子让给更早排队的人
- 两种下车方式：**扔掉行李回站台重搬**（recompute，费搬运工）vs **行李寄到站台储物柜**（swap 到 CPU 内存，费 PCIe 那条慢通道，02 篇算过）。vLLM 默认 recompute——因为重搬比走那条慢通道快
- 被请下车的人回到 waiting 队首，下一圈优先上

**决定 4：这一圈怎么开**（组 batch）
- 车上所有人各跑一圈拿一个字（decode）
- 新上车的人要搬行李（prefill）。搬整件会让全车等 → 切成几圈搬（chunked prefill），每圈搬一部分、同时给老乘客送字
- 有小跟班（投机解码）的话：跟班先猜 k 个字，这一圈司机一次验 k 个，对了全收，错了从第一个错处截断

四个决定做完，发车。跑完一圈，回到决定 1。

## 三、行李架的账本：block table

Phase 0 只说了「按箱寄存」。Phase 1 看清楚箱子怎么管：

- 行李架切成固定大小的格子（block，比如 16 个 token 一格）
- 每位乘客手里一张清单：我的第 1 格在架子第 37 号、第 2 格在第 4 号……（logical → physical 映射）
- 两位乘客前几箱一样（相同前缀）→ 清单指向同一批格子，一份行李两人用
- 其中一人开始往共用的格子里加东西 → 先复制一份再加（copy-on-write），另一人不受影响
- 03 篇的 hash 链是「怎么认出两箱一样」；block table 是「认出来之后怎么共用」

指标：`gpu_cache_usage_perc` 是行李架用了几成；`prefix_cache_hit_rate` 是上车的人里有多少箱是免搬的。

## 四、投机解码：跟班和司机

- 跟班（小模型）跑得快但会错；司机（大模型）一圈只能出一个字，但能一次**验证** k 个候选
- 一圈的成本：司机读一遍权重（油钱不变）+ 多算 k 个位置（算力）。跑圈本来在等油，多算几个字几乎不额外花时间——这就是收益来源
- 收益随车上人数递减：人多了每圈算力已经吃紧，再多验 k 个就撞发动机了（01 篇的 roofline 拐点）。所以投机解码是**空车时的加速器**，满车时收益消失
- 接受率 α 决定平均每圈多拿几个字：E[N] = 1 + α + α² + …

waiting ──准入──▶ running ──每圈 decode──▶ finished
  ▲                  │  ▲
  │  抢占(recompute) │  │ swap in
  └──────────────────┘  │
        swapped ────────┘
